# GPT-6 Luna inference trials — 2026-11-26

## Method

Three independent `gpt-6-luna` agents started without parent conversation history,
using separate fresh GitHub clones of commit
`b2f41997d3b368ce1b7873b92493a7cb679e10fd` on `feature/local-usage`.
They received the same musical brief, no suggested models and no earlier trial
results. Each read SKILL.md and its selected model guides. The evaluator-only
inference-validation.md was excluded. Inference ran sequentially across agents.

> Use gary4claude to make a 120-second instrumental electronic track at 120 BPM
> in A minor. Give it a memorable melodic hook, development in energy, and a
> finished ending. Choose the musical workflow yourself.

HTTP attempts, submitted settings, results, local exceptions and branch decisions
were retained outside the tracked repo. No training or deployment changes were
made. Two further musical-intent probes cover changing timbre within a loop and
editable-score continuation; those are coverage tests, not additional samples
of this identical-brief comparison.

### Duplicate Submission After a Local Error

Session 02 raised `TypeError: unsupported operand type(s) for %: 'WindowsPath'
and 'int'` while constructing a polling filename after a successful submit.
It reran the combined submit/poll script and created another job with identical
settings and seed. The two POSTs were logged five seconds apart, and the first
job was not known terminal before the second POST. Service FIFO serialization
was not compliance with the skill's wait-before-submitting rule.

Both jobs and outputs were preserved; both were confirmed done before the final
cover. The evaluator requested preservation of the exception and job timelines,
without supplying musical choices or recovery code. This was a local agent
execution error, not a failed API request or a backend defect. Existing queue
instructions already prohibited the duplicate; the follow-up recovery guidance
makes the local-error case explicit.

### Selection and Instruction Bias

All three sessions chose Carey text2music because its guide offers explicit
full-song duration, BPM, key and instrumental controls. This is a reasonable fit
for this particular brief; it does not establish that Luna would choose Carey
for loops, stems or score editing, or that the overall skill is unbiased.

All three decision records attributed the subsequent cover to the skill's normal
full-song polish rule. None had listening evidence that a cover was needed or
better. That was direct procedural steering, not an independently established
musical preference. The follow-up docs make polish optional and allow a single
generation to satisfy a brief. They do not force model variety or add a random
model rotation to conceal the narrow baseline choices.

## Coverage Probes

### Session 04: Evolving Eight-Bar Loop

Brief: make an eight-bar instrumental electronic loop at 120 BPM in A minor,
evolving from gritty guitar into playful digital arpeggios within one coherent
groove. The brief named no model or API feature.

Luna chose SA3 `/generate/loop`, discovered lane support and adapter ids, and
used independently prompted `kev` and `keygen` lanes with opposing strength
curves. It sent explicit `loras: []`, `shift: none`, eight steps and the
0.5625 averaging threshold from the worked example. The result metadata echoed
both lane prompts/settings. The inspected WAV has 705,600 frames at 44.1 kHz,
stereo PCM16: exactly 16 seconds, or eight 4/4 bars at 120 BPM.

One local `ModuleNotFoundError` came from assuming `requests` was installed;
Luna recovered using urllib. All 28 recorded HTTP attempts returned 200. There
was one generation POST and 23 status GETs, **all already completed**: 22 were
unnecessary repeat downloads. The client removed `audio_data` to save it, then
used its presence as the polling stop condition.

The observer found the log still growing after Luna's final answer and requested
cleanup. Luna stopped its exact owned Python polling process; the parent checked
that it was gone. Final log count was 29 records (28 HTTP plus the local import
exception), not the smaller counts initially reported. No generation was
repeated. This was a polling lifecycle error, not an API failure. The new shared
guidance checks process exit, and sa3.md now has a stdlib example that exits on
terminal status before decoding; the example was verified against a simulated
generating → completed response sequence with no extra GET.

### Session 05: Editable Score and Continuation

Input was a byte-identical copy of session 04's WAV, without its decision log
or previous agent context. Brief: recover an editable melody/chord score, make a
sensible chord/motif change, then render eight new bars beyond the recovered
source score, keeping intended 120 BPM/A minor/instrumental character.

Luna chose Yuey full transcription → hand edit of ABC → `/generate` with
`abc_prefix`. Transcription recovered eight bars, `Q:1/4=120`, `K:Am` and 4/4.
It changed the second block's F chord to Dm, preserved the voice durations, and
requested `target_bars: 16` with an outro. The final metadata reports 16 score
bars, 32 seconds nominal score duration, and 39.998667 seconds of rendered
48 kHz stereo PCM16 audio. The score was not ABC-truncated. This was score
continuation/re-render, not encoded-audio continuation; semantic prefix duration
was zero. Original, edited-prefix and final extended ABC and MIDI were saved.

There were 11 recorded HTTP attempts, all 200, including two compute POSTs.
One local SyntaxError in a one-line bar-count inspection command was corrected
by moving the check into a script; no blocking API contract ambiguity was
reported. A preliminary
progress message called the 16-second input 16 bars, but the saved transcription
and actual request correctly used eight source bars plus eight new bars.

### Coverage Summary

Across all five sessions: **82 recorded HTTP attempts, no HTTP errors, ten
accepted compute jobs instead of nine intended jobs**. Client correctness still
failed in the duplicate-submission and runaway-poll cases. The targeted brief
elicited SA3 lanes and Yuey score continuation rather than requiring those model
names in an ordinary music brief; these probes are not independent evidence of
general model-choice diversity.

These trials did not exercise SA3 continuation lane offsets/transform, Yuey
encoded-audio continuation, Carey Complete accompaniment or lego vocal assembly.
Their documented contracts still need targeted live trials and audition.

## Follow-up Guidance Changes

- Save raw submission responses and ids before local post-processing, using
  per-job files; separate submit from poll/fetch stages.
- Resume an existing job after a local exception. Reprocess saved MIME/WAV bytes
  or repeat result GETs instead of creating another generation.
- Identical seeds/payloads are not idempotency keys. Unknown POST outcomes need
  reconciliation, not blind retries; a queue does not replace terminal-state
  checks.
- Make cover/transform polish a musical choice, without claiming an extra pass
  improves music that the agent cannot hear.
- Use terminal status to exit polling before extracting/removing payloads; provide
  a working stdlib SA3 polling example and check that owned pollers actually exit.
- Prefer available stdlib/curl clients rather than assuming `requests` is installed.
- Evaluate local exceptions, duplicate POSTs, repeated completed downloads and
  post-final-answer process cleanup as well as HTTP status.

The trials above used the original pinned revision, not the follow-up edits.
These results do not prove that revised wording prevents every agent mistake.

## Limits and Local Evidence

This is a small qualitative sample with one fixed genre/tempo/duration brief.
No agent could audition audio. Duration, format, peaks and successful transport
cannot verify the hook, harmony, timbral transitions, ending or listening quality.
The user should audition takes before treating them as successful music.

Raw evidence and audio remain under
`C:/dev/gary4claude-evals/20261126/session-0N/outputs/trial/` in each clone:
`api_attempts.jsonl`, `decisions.md`, request/response files and WAVs. Parent
summaries and WAV hashes are under the main checkout's ignored
`outputs/luna-evaluation-20261126/`. They are not included in a fresh Git clone.
The source commit and briefs above allow another machine to rerun the trials;
new takes and timings need not match these runs.
